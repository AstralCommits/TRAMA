O que foi adicionado:

  comparação de faturamento, diferença em reais e cenários salvos.
- Gerenciamento de Categorias (limite de 50 caracteres e prevenção de duplicidade).
- Gerenciamento de Confecções (Toritama, Caruaru e Santa Cruz do Capibaribe).
- Lançamento mensal de vendas usando as categorias e confecções cadastradas.
- Os três módulos administrativos aparecem apenas para o perfil Administrador.
- Dados persistidos no localStorage por conta/navegador, seguindo o padrão já usado
  pelo projeto. Isso não é persistência em servidor/backend.

Para testar:
1. Extraia o projeto completo.
2. Abra a pasta Frontend/apps/web no terminal.
3. Use Node.js >= 22.22.0 (versão exigida no package.json).
4. Execute npm ci e depois npm run dev.
5. Entre na demonstração com perfil Administrador para visualizar todos os módulos.

Observação: o ambiente de execução desta entrega não conseguiu concluir a instalação
das dependências, portanto não foi possível executar o build/typecheck. Os arquivos
foram integrados à estrutura existente, mas valide com npm run typecheck e npm run build
antes de fazer o push.

Pontos importantes para integração:
- O catálogo utiliza itens demonstrativos locais, pois o ZIP recebido não contém uma API/catálogo público de artesanato para carregar peças reais. Substitua os itens de demonstração por dados do backend quando esse serviço estiver disponível.
- O frontend espera que POST /api/cotacoes retorne um dos campos de protocolo: protocolo, protocol, numeroProtocolo, protocoloAtendimento ou numero_protocolo. Ajuste o mapeamento caso o contrato real do backend use outro nome.
- O projeto incluído neste ZIP não contém implementação backend para /api/cotacoes. A solicitação só será registrada quando esse endpoint estiver implementado e acessível pela VITE_API_URL (padrão atual: http://localhost:8080).
- A instalação de dependências/build não foi concluída neste ambiente; validar com Node.js >= 22.22.0, npm ci e npm run build em ambiente compatível antes do merge.
